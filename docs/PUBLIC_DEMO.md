# Временная ссылка для показа заказчику

Дополнительные пакеты не нужны: используются установленный Node.js, готовая сборка сайта и штатный OpenSSH. Внешний сервис: [localhost.run](https://localhost.run/docs/). Не требуются регистрация и платный тариф.

## Запуск из собственного окна Windows

Откройте папку проекта в Проводнике и дважды нажмите `START_PUBLIC_DEMO.cmd`. Он использует установленный Node.js (в том числе встроенный runtime, если Node отсутствует в PATH), не устанавливая пакеты. Сборка сайта должна уже существовать.

Не закрывайте открывшееся окно. После проверок в нём будут ссылка и новые пароли для трёх ролей. Этот способ не зависит от срока жизни служебного процесса, запущенного ассистентом. Старые ссылки и пароли не действуют для нового запуска.

При повторной ошибке пришлите текст из окна. Состояние и причины остановки записываются в `status.json`, события SSH и смены адреса — в `tunnel-events.jsonl` внутри каталога конкретной демонстрации. Журнал не содержит рабочих медицинских данных. Обрыв туннеля и смена адреса больше не завершают демонстрацию немедленно: запускается восстановление, описанное ниже.

## Запуск через терминал

Из корня проекта:

```powershell
pnpm --dir web build
pnpm --dir web demo:public
```

Сборка использует уже установленные зависимости; команда демонстрации ничего не скачивает. Если Node или pnpm отсутствуют в PATH, сначала добавьте уже установленный Node в PATH; не запускайте установку пакетов ради этой демонстрации.

После проверки публичной страницы/стилей и входа под тремя ролями на изолированном демо-сервере появится HTTPS-ссылка. Проверки ролей идут напрямую по loopback с правильным публичным Host/Origin, чтобы не создавать множество соединений к бесплатному посреднику и не останавливать запуск из-за тайм-аута одной из них. Для посетителя обычный вход через публичный сайт не меняется; подтверждение MFA по-прежнему обязательно. Доступы находятся в локальном файле `web/.data/public-demo/run-*/access.json`, путь к конкретному файлу выводится при запуске. Передавайте только нужные демонстрационные учётные записи, а не весь файл. Не публикуйте пароли в открытых каналах.

После обновления 05.10.2026 обязательный второй фактор администраторов действует и в демо. Проверка запуска теперь проходит его полностью, а не ожидает прямой переход после пароля. В окне выводятся десять случайных одноразовых **демо-кодов** для каждого администратора. После логина/пароля нажать «Продолжить с аутентификатором» и ввести один неиспользованный код. Для повторного входа нужен другой код. Можно вместо этого добавить демо-ключ из `access.json` в приложение-аутентификатор. Обычная проверка запуска не расходует резервные коды; после неё перезапускается только собственный демо-процесс для проверки доступности после перезапуска.

Второй фактор сохраняется в `run-*/mfa.enc` под отдельным случайным демо-ключом. Рабочий MFA-файл, PostgreSQL и приватный `website.env` в этот контур не подключаются. Ошибка теперь выводит код завершения и путь к диагностике, а не сообщение об обычной остановке. Локальная проверка без публикации: `node scripts/public-demo.mjs --check-local`; она не выводит пароли/коды и не меняет указатель текущего публичного запуска.

Исправлен сетевой сбой проверки после перезапуска: GET-проверки не удерживают старое соединение и повторяются ограниченное число раз при сетевой ошибке/502/503/504. TLS-проверка не отключается, POST-вход/подтверждение MFA не повторяются автоматически. В `status.json` сохраняется этап и код причины вместо одного `fetch failed`. `node scripts/public-demo.mjs --check-public` проверяет настоящий временный публичный туннель и закрывает только его, не выводя пароли и не меняя указатель текущего демо. 05.10.2026 этот сценарий прошёл, включая доступность после перезапуска; бесплатный сервис всё равно не гарантирует постоянную работу ссылки.

## Восстановление соединения — 28.10.2026

При завершении SSH-соединения скрипт создаёт новый туннель. При смене домена живого туннеля он принимает новый адрес, а не останавливает показ. Используется до пяти попыток на один эпизод восстановления с паузами 1, 3, 5 и 10 секунд; ожидание выдачи адреса ограничено 30 секундами на попытку. Keepalive SSH проверяет соединение каждые 15 секунд. Неограниченного цикла при недоступном сервисе нет: после исчерпания попыток выводятся причина и путь диагностики.

Новая ссылка выводится как «Демонстрация снова доступна» только после успешной проверки страницы входа и её стилей. При новом домене перезапускается только изолированный сервер демо с новым `APP_ORIGIN`: проверки источника запросов, HTTPS и второй фактор не отключаются. Сам вход и подтверждение MFA автоматически не повторяются. Изначальная проверка доступа всех трёх ролей остаётся обязательной.

При восстановлении сохраняются каталог запуска, зашифрованные осмотры, учётные записи, сеансы, ключи и уже настроенный второй фактор. Пароли и одноразовые коды не генерируются заново; использованные коды не становятся доступными повторно. При смене домена посетителю нужно открыть новую ссылку и снова войти: cookies не переносятся между доменами. Несохранённый ввод формы на старом домене автоматически не переносится. Передайте заказчику обновлённую ссылку из окна запуска.

В `access.json` и указателе текущего запуска обновляется адрес. Во время восстановления `status` равен `reconnecting`, а действующая `url` отсутствует (`null`), чтобы не выдавать прежнюю ссылку за проверенную. После остановки адрес также не считается действующим. Если открыто несколько отдельных окон демо, старый запуск при восстановлении не перехватывает указатель `demo:stop` у более нового.

Проверки без вывода паролей и без изменения указателя текущего показа:

```powershell
node scripts/public-demo.mjs --check-local
node scripts/public-demo.mjs --check-public
node scripts/public-demo.mjs --check-recovery
```

Последняя проверка создаёт собственный временный публичный туннель, выполняет проверки ролей, принудительно отключает только свой SSH-процесс и восстанавливает связь. Проверяются неизменность файлов осмотров/учётных записей/MFA до повторного входа и вход всех ролей после восстановления с уже сохранённым вторым фактором. Для этой проверки расходуется по одному коду только её отдельных тестовых администраторов. После проверки собственные сервер и туннель закрываются. Проверочные режимы дополнительно выполняют восемь неверных входов подряд и убеждаются, что неправильный пароль отклоняется, но cooldown не появляется и правильный вход после этого работает. Автоматические тесты восстановления, смены адреса, поздних SSH-событий, ограниченных повторов и отмены включены в `pnpm test:demo`.

28.10.2026 прошли 14 автоматических тестов, проверка ESLint изменённых скриптов, локальный запуск со всеми ролями и две проверки с настоящими публичными туннелями и принудительным обрывом. Повторный прогон дополнительно проверил обновление адреса/статуса в собственном `access.json` и неизменность реквизитов/срока. Указатель действующего показа `active.json` эти проверки не меняли. Это проверка восстановления, не длительный тест непрерывной доступности бесплатного сервиса.

Официальное описание обрывов, keepalive и самостоятельного переподключения: [localhost.run FAQ](https://localhost.run/docs/faq/#my-connection-is-unstable-tunnels-go-down-often). Это механизм восстановления, а не гарантия постоянного адреса или доступности посредника.

Оставьте компьютер включённым, подключённым к интернету и окно запуска открытым. Ограничение длительности в четыре часа снято: у запуска `expiresAt: null`, автоматической остановки по длительности или бездействию нет. Ctrl+Q и `demo:stop` учитываются и во время повторных подключений. Ctrl+C не останавливает демо, а выводит подсказку о Ctrl+Q. Блокировка Windows не равна остановке демо, но сон/выключение ПК и потеря сети прерывают доступ; параметры питания Windows скрипт не меняет. Постоянный адрес и гарантированная круглосуточная работа требуют отдельного размещения.

В изолированном демо нет ожидания после неверных логинов/паролей и кодов MFA. Исключение включается только серверной настройкой запуска и проверкой файловых путей отдельного `run-*`, отключённых PostgreSQL/приватного окружения/offline. В рабочем сайте и PostgreSQL-режиме ограничения остаются прежними, даже если случайно выставить один demo-флаг. Проверка пароля, обязательный второй фактор, запрет повторного использования TOTP/резервных кодов и отзыв сеансов сохраняются. Сетевые паузы между попытками переподключения также остаются, чтобы не атаковать недоступный посредник частыми запросами.

Истечение онлайн-сеанса не выключает сервер: стандартный срок полного входа остаётся 8 часов, предварительного входа администратора до MFA — 10 минут. После истечения сеанса достаточно снова войти. Это не таймер бездействия и не ограничение времени работы демонстрации.

Проверка этой правки: production-сборка и ESLint прошли; 21 тест демонстрационного режима/его изоляции и 60 основных тестов прошли. На настоящем изолированном сервере проверены восемь неверных паролей подряд и по восемь неверных MFA-кодов для обоих администраторов с успешным правильным входом после них. Проверен публичный запуск с принудительным обрывом/восстановлением, сохранностью данных и `expiresAt: null`. Многочасовой тест доступности внешнего сервиса не выполнялся.

Остановить текущий запуск: **Ctrl+Q** в его окне. В обычном интерактивном терминале включён посимвольный ввод, чтобы Ctrl+C не посылал сигнал остановки. При завершении исходный режим терминала восстанавливается. Если терминал не поддерживает такой ввод, появится предупреждение; используйте `demo:stop` из другого окна. Закрытие самого окна всё ещё завершает демонстрацию.

Замена клавиш проверена в настоящем Windows TTY: Ctrl+C выводит подсказку и оставляет процесс работающим, Ctrl+Q вызывает остановку. Пройдены 18 автоматических тестов управления/авторизации/восстановления и повторный локальный запуск со всеми ролями. В последующей правке четырёхчасовая автоостановка снята; клавиши не менялись.

Из другого окна можно остановить последний запуск:

```powershell
pnpm --dir web demo:stop
```

## Изоляция и ограничения

- Только отдельная демонстрационная больница, случайные пароли трёх ролей и изначально пустая история. Никакие рабочие хранилища не копируются и не читаются.
- Производственный режим запуска без известного пароля разработчика. Отдельные случайные ключи сессий и шифрования.
- Сайт слушает только локальный адрес 127.0.0.1; наружу открывается лишь этот демонстрационный сайт. SSH не использует личные ключи пользователя.
- Офлайн-доступ отключён, платёжные секреты и интеграции не используются. Вручную внесённые платежи в этом запуске — только тестовые.
- На всех страницах есть предупреждение о демо. Указан запрет индексации; он не является ограничением доступа. Обязательный вход и серверные проверки ролей сохранены.
- Сервис localhost.run завершает HTTPS у себя и передаёт трафик по зашифрованному SSH-туннелю. Он является посредником, поэтому **не вводите реальные персональные или медицинские данные, рабочие пароли, реквизиты и секреты**.
- Изменения сохраняются только внутри каталога конкретного запуска. При новом запуске создаётся новая пустая демонстрация; старые тестовые файлы остаются локально, но прежние пароли и сессии не принимаются новым запуском.
- Это средство показа интерфейса заказчику, не развёртывание для клинического использования и не замена защищённому серверу больницы.
